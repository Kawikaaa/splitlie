# AI 助理 Sprint 6–8 首版

2026-11-01。基于现有 React/Vite/Supabase 实现，不是换肤或新聊天页。状态：功能首版与云端基础已落地，受限试点；完整模型评测和多会话验收仍未完成。优先结合 PROJECT_STATUS.md 阅读。

## 使用入口

- **小票**：添加交易 → 拍照识别小票 → 选择照片 → 旋转/裁切与预览 → 确认发送 → 详细录入核对 → 选择账户/付款状态 → 勾选核对 → 保存。交易详情可查看、编辑商品行。
- **周报**：概览 → 查看每周回顾 → 本周消费助理。先选目标，主动确认发送汇总；保留原有规则周报，生成失败不影响原有内容。
- **建议与行动**：在周报内选择试一试、暂不采纳，或将大额购买标为一次性/必要支出。接受后保存回顾日期；下周打卡区域展示到期行动，可反馈是否有帮助；周报中也可回看行动。

## 小票与账务

JPEG/PNG/WebP，原文件最多10MB、解码最多2400万像素；客户端按EXIF方向解码、旋转/裁切、缩至最长2048像素且最多240万像素，重新编码为JPEG。清除APP1–APP15/注释段，包括浏览器canvas附加的ICC色彩配置；服务端检查JPEG头、分段、尺寸和请求体上限，不接受远程图片URL。HEIC需先转换。

每次只识别一张票、一笔支出。预览支持整体/原尺寸切换，放大区域可触屏滚动、聚焦后用方向键移动，再旋转/裁切。商家、日期、币种、最终总额、商品名称/数量/行金额及额外税/小费/折扣进入可审核结果。缺失值不由模型补造，主表单的设备日期或空间币种只是可修改默认值，缺失识别字段仍提示核对。分类先用“其他”，不根据卡号猜账户。

金额用四位小数整数单位核对。已计入行金额的税/折扣不能重复加入；差额与无法核对情形均展示并要求勾选确认。编辑总额、币种、日期、描述或类型，以及明细/调整项后，核对状态重新取消。未核对时保存按钮禁用，服务端再次校验。

`transactions.receipt_data` 是独立结构化JSONB字段，包含商品行与识别来源，不塞入描述。它与交易行及原有账户触发器处于同一数据库事务。总额/币种/日期必须与交易主字段一致，只允许本人个人空间支出。整张票仍只计一笔消费；商品行不生成额外交易。详情与原有编辑入口复用同一明细组件。

原图/预览仅存在于本次浏览器内存和识别请求，不进入Storage、数据库或公共URL；保存的是结构化字段、模型名、图片SHA-256及用户核对状态。关闭弹窗释放图片。模型提供商的数据处理政策仍需在对外推广前复核；不承诺第三方零留存。

重复检查用服务端计算的清理后图片SHA-256，以及商家/日期/总额/币种相同记录，只提醒、不自动删账。修改裁切或编码可能改变哈希，因此不保证发现所有重复。小票新增重试复用客户端UUID；重复ID后读取本人已存记录，只有完整负载一致才恢复成功。失败和取消不自动写账。

## 周报与建议的可信边界

`ai-assistant` 使用来访者JWT校验真实用户，以该用户的RLS客户端查询本人个人空间。最多读取本地日期对应本周及前四周、6000条记录；任何查询失败或截断均返回不可用，不能充当零记录。

程序计算已付净消费、退款、分类、笔数、最大一笔及此前有记录周的均值。转账/还款/未支付支出不算已花费；退款按到账日冲减。未知换算数据排除并显示数量。无记录周不作为零消费；少于两个有记录历史周不生成比较观察。始终说明记录完整性未核实、本周可能仍在进行中。

AI不重新算数，也不自由编造因果。模型从服务端根据事实生成的观察ID和行动ID中选择最多三条观察、一个行动。页面用五语言模板呈现，并将数值直接绑定事实；未知ID、重复观察、额外自由文本和不受支持的行动均拒绝。它是受约束的解读首版，尚不是开放式咨询助手。

发送给百炼的内容仅有汇总、目标、日期和类别；不发交易描述、账户名称/余额、邮箱、图片、内部交易ID。页面依据链接保留在本地，可按日期/类别/具体记录打开交易列表，支持清除来源筛选；切换空间清除旧筛选。

报告按本人/空间/周/语言保存，事实指纹覆盖源记录版本、日期、币种、目标、模型和提示版本。重新打开时重新读取事实；修改、退款、重新分类或目标改变使旧解释过期。模型结果生成期间若另一个会话修改账本，报告仍表示生成时快照；重新打开校验，不承诺实时推送。

目标可修改/清除，行动和反馈独立持久化，均不修改账务。只保存用户明确选择，不推测收入、健康或家庭画像，不把相关变化当成行动的因果效果。周期费用目标目前提供原支出计划入口，尚未加入周期识别与订阅诊断。

## 服务端配置与配额

沿用已配置的百炼北京 `qwen3.8-flash`、专用受限密钥与免费额度保护。没有新密钥、SDK、套餐或付费回退。

- `AI_PARSER_ENABLED` 与 `AI_FREE_QUOTA_CONFIRMED`：原有总开关。
- `AI_RECEIPT_ENABLED=true`、`AI_WEEKLY_ENABLED=true`：新能力独立开关；缺失时拒绝模型调用。
- `AI_EVALUATION_ENABLED`：仅固定虚构周报样本调试，默认关闭；联调后须恢复false。样本模式不查真实账本、不保存报告，仍需鉴权、个人空间归属和正常配额。
- 同原文字草稿共享：每用户10次/UTC日、20秒冷却，全局50次/UTC日。
- 子限额：小票4次/用户/UTC日，周报3次/用户/UTC日，不增加总额度。已命中报告和只读查询不调用模型。
- 先调用既有service-only `reserve_ai_parse_quota`完成原子总额预留，再对service-only子计数表作条件写入；失败或竞争拒绝调用，可能消耗一次总尝试但不放行未计数调用。不新增特权公共RPC，也不扩大service_role账务读取权限。
- 图片/输入体积、最多2800输出tokens（小票）或200（周报）、25秒上游超时、32秒客户端超时；无自动重试。仍未实现完整token钱包/成本账本或跨请求并发预算。

运行日志不写图片、提示、密钥、账本内容或原始模型输出；私密报告表按上述规则保存事实包与已校验的观察/行动ID。子配额表当前没有自动TTL任务；只含用户ID、UTC日、任务和次数，后续可补定期清理，不宣称已有7日自动清理。联调结束已将`AI_EVALUATION_ENABLED`改回false；当前共享用户日尝试10/10，UTC零点恢复，不绕开配额完成全样本评测。
