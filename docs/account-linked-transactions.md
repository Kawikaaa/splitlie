# Account-linked transactions and form refinement

User-approved rules: account association is optional; income adds to an asset account; foreign currencies use the existing website FX service. Paid expenses deduct once. Upcoming expenses move no funds until paid. Credit-card expenses increase debt, and income decreases debt. Insufficient balance/debt blocks the entire save, with no partially saved transaction. Existing transactions are unlinked; no historical deductions are backfilled.

My Money is now `/my-money` for personal spaces only. Creation/editing uses the shared focus-trapping ModalSurface, a portal to the app shell, Escape/backdrop close when idle and scroll lock. Mobile actions stay visible. The transaction form uses the incumbent white/charcoal/lime system, with compact controls and account selection visible in manual and quick-entry modes. The quick parser and existing shared splits remain available. Saving refreshes the My Money page.

The database migration `opt_in_transaction_account_movements` adds opt-in columns and a SECURITY INVOKER private trigger. It uses ordered account row locks, server-calculated native amount, ownership/personal-space checks, nonnegative balances, and atomic old/new movement differences for edits, relinks, unlinks and deletes. Transactions keep their locked conversion rate when re-opened unchanged. Account currency/type changes are refused while transactions reference the account. Archived accounts can have existing transaction metadata edited and old movements reversed, but cannot receive changed/new movements until restored. Personal edits compare updated_at and fail visibly on concurrent edits.
