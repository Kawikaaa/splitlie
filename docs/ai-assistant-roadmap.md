# Splitlie AI 助理路线图

> 2026-11-01 · 路线图与验收门槛。随后用户授权推进多个Sprint及云端合成联调；Sprint6–8首版实现见[当前记录](ai-assistant-sprints-6-8.md)。本文列出完整目标，不表示所有门槛已通过；后台通知仍未授权或实现。

## 产品目标

把现有文字草稿扩展成日常记账助理，贯穿：轻松记录 → 看懂变化 → 选择一个小行动 → 下周回顾。

用户应能拍小票生成可核对的消费记录，读到有依据的周报，获得符合自身目标的建议，并通过自然语言追问。财务引擎负责算数和账务规则，模型负责提取、解释和表达；用户决定是否保存或调整计划。

推荐顺序：**Sprint 6 小票记账 → Sprint 7 AI 周报 → Sprint 8 建议与小行动 → Sprint 9 对话式查账**。账户专属流水、核对与既有验收缺口继续保留，不因 AI 接入而取消。

## 规划时的基础与模型判断

以下“已有/未有”描述开发开始前的状态；当前Sprint6–8首版及未通过门槛以[本轮实现记录](ai-assistant-sprints-6-8.md)和PROJECT_STATUS最新更新为准。

- 已有：可选文字 AI 草稿、服务端鉴权/配额、北京 qwen3.8-flash 与免费额度保护；规则型周总结、分类/消费信号、周打卡、预算与 Safe to Spend、账户关联/退款/转账。
- 未有：图片识别端点、图片隐私/存储流程、商品明细数据模型、生成式周报、建议追踪、自然语言数据查询工具。
- 2026-11-01 查阅百炼[视觉理解文档](https://help.aliyun.com/zh/model-studio/vision-model)：qwen3.8-flash 支持图像理解、文字提取及结构化输出。可以先评测当前模型，无需预先决定换模型。
- **模型有视觉能力，不等于产品接口已支持图片。** 当前接口只接受最多 300 字的单笔文本，输出/配额也按该任务设计。小票、周报、问答需要各自的输入契约、预算与验收。
- 当前免费额度是有限试用，不能当长期免费运行承诺。[免费额度规则](https://help.aliyun.com/zh/model-studio/new-free-quota)及账户实际余额/到期日需在启用新能力时复核；不自动使用付费回退。

## Sprint 6 — 拍小票记账

**用户流程：** 添加交易 → 拍照或上传 → 旋转/裁切与预览 → 确认发送 → 识别 → 核对总额、日期和明细 → 手动选择账户/付款状态 → 保存。

首版范围：

1. 一张小票、一笔支出；先支持清晰的 JPEG/PNG/WebP。手机拍摄、图片方向和失败提示纳入验收，不能假定所有 HEIC 都可直接处理。
2. 提取商家、日期、币种、最终总额、商品名称/数量/金额；小计、税、小费、折扣在原图明确出现时单独识别。
3. 展示图片与结构化结果，字段可修改；看不清或矛盾处标成待确认，不根据商家所在地猜币种，不把小计当总额。
4. 用程序校验金额关系、合法日期和单位。折扣已计入行金额时不得再减一次；金额不平衡时展示差额并阻止无确认的保存。不能为了凑总额改写识别值。
5. 商品明细随交易原子保存，交易详情可重新查看/修正。整张票只计一笔支出，明细不是额外交易，避免重复计数。
6. 重复图片哈希和商家/日期/总额给重复提醒；相似票据不自动删除。保存重试沿用幂等操作标识。
7. 用户确认保存后才使用现有账户扣款、汇率与余额不足规则；不得根据卡号尾号自动选扣款账户。

技术与隐私：

- 独立图片识别入口，先复用当前模型；图像结构化输出必须经运行时校验，不套用文字草稿的 300 字协议。
- 上传前校验文件、解码/旋转、限制像素和体积、重新编码去掉 EXIF；提供裁切/遮挡提示，但不宣称能自动识别并清除所有敏感内容。
- 默认不建立长期原图档案；临时私有文件须有真实的清理机制。需要长期保存原图时另行提供明确选项。不能用公开存储 URL 暴露小票。
- 不接收任意远程图片 URL；服务端校验所有权及资源限额。图片中的文字、二维码和指令均视为票据数据，不能触发工具调用。
- 商品明细/识别来源需要新增数据结构、RLS及与交易的原子写入，不能只塞入描述字段后声称明细持久化完成。

交付门槛：

- 准备至少 30 张获准使用的合成或脱敏小票，分开记录清晰、模糊、长票、多币种/多语言、税/折扣/小费、重复与非票据样本结果。
- 分别统计最终总额/币种/日期准确率、明细正确率、纠正量、拒绝率、延迟和 token 消耗；不只统计 JSON 格式有效率，不预先承诺准确率。
- 不确定字段不能静默通过；未确认、取消、失败、重复重试均不产生账务写入；保存后重开详情仍有明细。
- 失败可返回手动记账，用户已输入内容保留。共享小票分摊、多图/PDF、逐商品分类拆账留到后续。

## Sprint 7 — 会解释变化的 AI 周报

**入口：** 升级已有 Weekly recap，保留原有数字、分类、趋势与消费信号。首版用户主动生成；后台自动生成和邮件/推送另行确认。

内容结构：

- 一段本周概况：主要变化、重要的一次性支出或持续模式。
- 最多三条值得注意的事实，区分总额变化、频率变化、单价变化；资料不足时不解释原因。
- 最多一个下周可尝试的小行动，说明依据，并提供查看对应记录/计划的入口。
- 数据范围、生成时间、记录完整性与比较基础；不足一周、无历史或长时间漏记时清楚说明。

可信实现：

- 由现有 financial/analytics 引擎先生成事实包：本地周边界、币种、净消费/退款、分类、频率、待支付义务、比较窗口与数据质量。
- 转账/还款不算消费，退款按收到日期冲减消费。模型不从原始行重新算总数、汇率或 Safe to Spend，也不把未支付账单计成已花费。
- 模型只引用服务端提供的事实 ID；数值组件直接绑定事实包。找不到来源、比较不足或输出冲突时拒绝该段并回退现有规则型周报。
- 首版尽量只发送汇总；需要具体交易描述解释时另行披露范围，移除邮箱/账户标识等无关数据。原有“发送当前文本”确认不覆盖整个账本。
- 按用户/空间、周、语言、事实版本和模型/提示版本隔离缓存；交易编辑、退款或重新分类导致事实变化时标记旧报告过期。
- 先支持主动生成及查看已生成报告。未获得授权不新增后台任务、对外通知或整库上传。

交付门槛：每项具体结论可追溯、金额/日期口径与现有引擎一致；覆盖零记录/少记录/漏记、历史不足、退款跨周、周期账单、转账及更改历史后的过期报告。不能只把现有算术换成更长的句子。

## Sprint 8 — 建议与小行动

**目标：** 把周报中的观察转成用户愿意尝试、能在下周回顾的行动。

- 用户可选目标：更清楚钱花在哪里、控制某类可选开销、检查重复订阅、保持当前节奏；偏好可修改/清除，不推测用户收入、健康或家庭情况。
- 每次给一至两条建议，附依据、适用条件和可选择的动作；没有明显异常也可以建议维持现状。
- 区分一次性大额与持续增长、必要支出与用户标记的可调整支出。资料不足先提一个问题，不用“应该少花钱”补空白。
- 允许接受、忽略、“这笔是一次性/必要支出”等反馈；只把用户明确选择存为偏好/上下文，不擅自训练模型或写入敏感画像。
- 接受建议后记录一个小行动及回顾日期，下周结合打卡回顾是否有帮助；描述为记录到的变化，不把相关性当成建议造成的效果。
- 涉及预算、周期账单或交易修改，进入原有页面的预填草稿，由用户核对并保存；建议本身不改账。

示例语气（虚构，非用户实际消费）：本周增加主要来自一次性购物，日常餐饮较稳定。如果这笔购买在计划内，可以先维持日常安排；如果下周仍有类似购买，可以提前在计划里留出空间。

配套：继续账户流水与余额核对，提供完整的证据入口。账单提醒及信用卡还款仍单独设计，不靠模型补齐财务语义。

交付门槛：建议有来源且符合用户目标；用户能拒绝/纠正；避免消费羞辱、未经证实的原因推断和投资/信贷产品推荐。反馈有持久化和回看闭环，而非只生成一段文案。

## Sprint 9 — 对话式查账助理

可先回答：这个月餐饮花了多少、本周为什么比上周高、哪些订阅快到期、这笔支出影响了哪个账户。

- 模型将问题转成受限查询意图；服务端限定用户/空间、日期范围、分类、返回条数与执行预算。
- 使用白名单工具查询消费汇总、交易、计划、周期账单与账户流水；程序计算结果，模型组织说明。无需向模型开放任意 SQL 或整库访问。
- 答案显示时间范围、币种、数据质量及来源入口；模糊问题先澄清，不能凭空补金额或假装读到了未授权的数据。
- 多轮上下文保留当前问题必要的结构化筛选条件；私密个人空间与共享空间不能混查，默认不发送无关聊天历史。
- 初版只读；“帮我修改预算/补一笔交易”只准备可审核草稿并跳转原流程，不能自动保存、结算或移动账户余额。

交付门槛：固定查询测试集与引擎答案一致、越权/提示注入被拒、来源可打开；拒绝的数据与真正的零值分开；每轮工具调用有限，不形成无限循环。

## 跨 Sprint 的共同基础

1. **功能分开配置。** 文本、小票、周报、建议/问答有独立 feature flag、契约与预算，服务端可换模型；先保持当前 Supabase/React 架构，不为路线图引入 SDK 或向量库。
2. **额度按真实成本。** 在现有 10/用户/UTC 日、50/全局/UTC 日基线上制定共享总预算与功能子限额，再增加图像大小、输入/输出 token、并发和超时上限；当前 SQL 还不是完整 token 预算器。没有测量前不自动提高限额。
3. **隐私按任务披露。** 小票图片、周报汇总、对话查账分别说明将发送什么；不把文字解析的同意视为其他功能的授权。复核提供商实际隐私/日志条款，不承诺未验证的数据保留政策。
4. **输出是非可信数据。** 服务端 schema、事实来源、金额关系与用户权限必检；安全渲染，不执行票据/交易描述或模型输出中的指令。
5. **失败可继续使用产品。** 模型超时/额度耗尽保留输入和手动入口；周报保留规则结果，报错不显示零；取消或迟到响应不落账。
6. **评测和进度真实。** 每轮记录模型、提示/协议版本、合成案例 ID、字段/事实错误、纠正量、延迟与消耗，不记录真实原文/原图为日志。既有 25 条文字评测与并发缺口继续补齐；不为当日跑完评测绕开配额。
7. **界面沿用现有系统。** 开发前看真实界面，复用现有组件，并按用户要求使用 Build Web Apps 与 Impeccable；本次规划不更改 UI。

## 状态与下一步

四个 Sprint 均为建议计划，尚未开工。下一步建议锁定 Sprint 6 的单票范围，先完成真实视觉调用与样本评测，再实现图片审核、结构化明细与原子保存。若样本显示当前模型不达标，再讨论替换模型或 OCR 方案及其额度，不自动转付费。

本文替代旧路线图中“OCR 暂不优先、先完成全部账户闭环再做 AI”的排序；账户闭环仍保留，AI 基础可靠性也不因功能增加而免验收。
