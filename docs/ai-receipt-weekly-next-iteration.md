## 分批执行与退出门槛

### P0-A 本地可靠性与事实修正

1. 把规格§9逐条映射到可运行用例，并明确既有132项测试是上次交付结果，本次修改后需要重新运行。
2. 修正周区间/可比期设计，统一与现有财务引擎的适配；不改变退款、转账、Safe to Spend或共享账务规则。
3. 补小票草稿生命周期、取消/迟到结果/重复提交和未知金额核对用例，先修实际失败项。
4. 设计旧报告失败恢复、跨范围清空、历史缓存与来源失效的测试。

退出门槛：可比性与财务不变量用例通过；失败不被当零；取消/迟到结果不覆盖；新增测试与全量回归、构建通过。涉及界面变更时先实际查看页面并按技能流程验证。

### P0-B 隔离环境与真实验收

1. 先提交测试环境、允许写入/删除的合成数据范围、外部模型发送范围、额度安排及回滚方案。
2. 在取得相应许可后，执行专用测试账户的上传→识别→修改→确认→保存→刷新/重新登录→重开→修改→删除，以及失败/并发/重复提交。
3. 30张小票分桶评测分别记录总额、币种、日期、商品行正确率、纠正量、拒绝率、延迟和token消耗；保留失败，不拿模拟响应计入真实识别准确率。
4. 验证历史周报告的读取、交易/退款变更、过期与恢复，不为了测试直接污染真实账本。

退出门槛：规格§9的P0用户级用例有对应证据。日额度不够时记录未运行项并分日安排；不得自行提额或开启后台自动评测。

### P1 审核效率与周报内容

- 小票：可放大图与原表单的布局协调、字段来源/错误定位、重复记录查看、商品长列表、已有商家分类建议。
- 周报：统一完整视图、最多两条有用观察、一个周主要行动、兼容完成反馈、历史状态和来源入口，Overview只保留必要预览。
- 契约或数据结构调整先做本地兼容提案；不把本地代码、数据库迁移、Edge部署和前端上线混写成一个状态。

### P2 只保留提案

对话式财务助理、推送、银行同步、自动预算/账单创建、复杂商品级分摊、Shared关联等不进入本轮实施。
